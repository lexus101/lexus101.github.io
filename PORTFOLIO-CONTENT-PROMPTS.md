# Portfolio content prompts — answer in rough notes, not polished prose

You do **not** need to write an essay. For any project you want to deepen, answer these in 1–3 sentences each. I can turn the rough answers into the final case-study copy later.

## The six questions that create hiring evidence

1. **Player problem** — What was confusing, boring, slow, unreadable, or not fun for the player?
2. **Design constraint** — What could you *not* solve by simply adding more UI, more rules, or more content?
3. **First attempt** — What did the earlier version do, and why was it not good enough?
4. **Decision** — What did you change, and why did you choose that solution instead of another one?
5. **Proof** — What can we show on the site that demonstrates the change? A clip, before/after, playtest observation, screenshot, or behavior is enough. Do not invent metrics.
6. **Ownership** — What was yours? What did teammates do? What parts were AI-assisted implementation versus your design/iteration decisions?

## What to show visually

- **Operation / interaction:** show it in a 6–15 second clip with a short caption. Do not explain every button in prose.
- **Thinking:** one compact Problem → Decision → Iteration → Result strip is enough.
- **Before / after:** use this whenever the visual or interaction changed meaningfully.
- **System diagrams:** only when the system cannot be understood from gameplay footage alone.
- **Code:** only show it when applying to technical roles and when the code itself proves something useful.
